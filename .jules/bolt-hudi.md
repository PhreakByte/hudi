## 2026-01-01 - [HUDI-PERF-BLOOM-INDEX] Bloom Index Redundant File Open
**Learning:** `HoodieBloomIndexCheckFunction` repeatedly creates `HoodieKeyLookupHandle`, which in turn repeatedly opens `HoodieFileReader` for the same file when not using Metadata Table (or when verifying keys). This redundancy causes high I/O latency, especially on object stores like S3. The `HoodieFileReader` (reading the footer/bloom filter) was being closed and then `HoodieIndexUtils.filterKeysFromFile` would open the file again to verify keys.
**Action:** Refactored `HoodieKeyLookupHandle` to be `AutoCloseable` and reuse the `HoodieFileReader`. Refactored `HoodieIndexUtils.filterKeysFromFile` to accept an existing `HoodieFileReader`. This pattern of checking if a resource is already open before creating a new one should be applied to other file-level operations.
